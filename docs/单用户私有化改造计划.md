## 2. 已实测确认的核心风险（含证据）

### 2.1 【已实测复现】游客 24h 清理任务会物理删除文件，且绕过回收站

**证据（改前基线，2026-09-11 实测）**：在挂载策略根下放一个 mtime 为 3 天前的文件，服务重启后该文件消失；同目录 24h 内的文件保留。

```
### 1. [改前] 初始文件清单（游客有效目录 = 策略根/guest）
-rw-r--r--  fresh.txt      (刚刚)
-rw-r--r--  old.txt        (2026-09-08 20:09，3 天前)
### 4. [改前] 重启后文件清单
-rw-r--r--  fresh.txt      ← 仅剩新文件
>>> 判定 A：old.txt 已被物理删除 → 危害复现（绕过回收站）
```

**机制**：`handler/tasks.go:70 sweepGuestWorkspace()` 每小时（且**服务每次启动时立刻执行一次**）遍历所有 `type=local status=active` 的策略，对游客身份解析出的物理根做递归 mtime 清理，`os.Remove` 直接物理删除，不进回收站。

**为什么会波及你的文件**：清理范围 = 游客身份在该策略下的有效根。

- 隔离**开启**时：有效根 = `<挂载根>/guest` → 目前只会删到游客自己的目录（所以现在还没伤到你）。
- 隔离**关闭**后：有效根 = `<挂载根>` → **清理范围直接变成你挂载的整个文件夹**。

> 这正是"关隔离"和"删游客"必须**同一批、且先删清理任务**的原因。顺序反了，一小时内就会丢数据。

### 2.2 【已确认】本地盘按用户子目录隔离，与"挂载即可见"直接冲突

```go
// server/main.go:26-32（webdav.go:52-59 有同一份）
root := p.RootPath
if dir := fscore.UserDirOf(u); dir != "" {
    root = filepath.Join(root, dir)   // 挂 E:\电影 → 实际访问 E:\电影\admin
}
```

改动点仅这两处 + `fscore.UserDirOf`（`local.go:319`，全仓只被这两处调用）。

### 2.3 挂载入口不在文件管理器里，且没有"选文件夹"能力

- 唯一入口：管理控制台 → 存储策略 → 挂载存储；"物理目录"是**纯文本框**（`AdminConsole.vue:668-671`）。
- 服务端**没有**列本机目录的接口（唯一的列目录端点是 SSH 远端的 `terminal/fs/list`）。
- 结论：**「分配菜单」是新增功能**，不是改造。

> ✅ 已在批次 6（`687325b`）解决：新增 `handler/localdir.go` 的 `GET /api/admin/fs/dirs`（列本机目录）与 Explorer 内的「挂载文件夹」浏览式目录选择器；管理台的物理目录文本框保留为备用入口。

## 5. 批次 1 附带要处理的事：用户组删除后，那些"组参数"怎么办

删掉 `UserGroup` 后，原先从组里读的参数必须有固定值，否则会出现"读了空组 → 配额为 0 → 什么都传不上去"这类静默故障。预定固定值：

| 参数 | 原来源 | 固定值 |
| --- | --- | --- |
| 配额 | `UserGroup.QuotaMB` | **不限**（单用户内网，自己的盘） |
| 回收站保留天数 | `UserGroup.RecycleRetentionDays` | 30 天（保持现状语义） |
| 版本保留个数/天数 | `UserGroup.KeepVersions` / `VersionRetentionDays` | 维持现有默认值 |
| 允许分享/WebDAV/压缩/离线 | `Allow*` 系列 | 全部 `true` |
| 只读 | `ReadOnly` | `false` |
| 应用权限 | `AppPerms` | 全部开启（等价于管理员） |

> ⚠️ 这一项的影响面比"删两个路由"大得多：`fscore/service.go`、`fscore/versions.go`、`middleware/auth.go`、`handler/fs.go`、`bt.go`、`share.go`、`tasks.go` 都读组参数。我会在**批次 2** 单独做，并配"配额不限制 / 上传下载正常"的实测。

### 7.6 批次 9 追加：手机端接入实测暴露的两个真缺陷（2026-09-11）

起因是问「运行以后手机端 WebDAV 怎么配账号密码」。为了给准确答案写了 `probe-phone.mjs` 走完整链路，结果**测出两个真缺陷**（都不是人为注入）。

**认证链路（先说清事实，避免继续按旧假设用）**

| 项 | 事实 |
| --- | --- |
| 账号 | 网页登录用户名（`admin`） |
| 密码 | **WebDAV 独立密码**（`PUT /api/users/me/webdav-password`，存 `user.webdav_password_hash`）——**不是**登录密码；未设置时服务端回 401「WebDAV 密码错误（请在设置中先行设置）」 |
| 地址 | `http://<内网IP>:18322/dav/`（统一入口）；单挂载 `…/dav/<挂载名>/` |
| 前置开关 | `SiteSetting.webdav_enabled`（默认 `true`，管理台可关，关后 403）与 `AppEnabled("webdav")`（清单默认启用） |
| 失败锁定 | 与网页登录**共用**同一张失败锁定表（IP+用户名，5 次锁 15 分钟）；认证成功即清零 |

**缺陷 ①：PUT 到「目录」会把目录删掉换成文件（数据破坏，已修）**

- 现象：`PUT /dav/<挂载名>/`（带内容）→ **`201 Created`**；磁盘上那个挂载文件夹已经**变成一个文件**（实测 `readdirSync` 直接抛 `ENOTDIR`）。
- 根因链：`LocalDriver.CreateFile`（`fscore/local.go:257`）是 `os.MkdirAll(Dir(phys))` → 写 `phys+".cp-part"` → **`os.Remove(phys)`** → `Rename(tmp, phys)`。当 `phys` 指向**空目录**时，Windows 上 `os.Remove` 对空目录**成功**，于是目录被删、临时文件改名顶上。目录非空时 `os.Remove` 失败，只是报错（相对安全）。
- 可达性：`webdav` 的 `handlePut` 不做 IsDir 前置检查，直接 `OpenFile(..., O_RDWR|O_CREATE|O_TRUNC, 0666)`；`COPY` 目标同理。
- 修法：在 `DavFS.OpenFile` 的写入分支先 `os.Stat(phys)`，命中目录就**返回拒写对象**而不是落盘 —— `davRejectWriteFile` 的 `Write`/`Close` 都返回 `errDavIsDir`，`io.Copy` 与 `Close` 任一失败都会让 webdav 落到 `405 Method Not Allowed`（RFC 4918 对"向集合 PUT"的规定），**一个字节都不落盘**。
- 实测：修前 `PUT` = 201 且目录消失；修后 `PUT` = **405**，`[目录] 内容=[]` 完好。`MKCOL`/`DELETE`/`MOVE`/`COPY` 到挂载根同样 4xx 且目录不受影响。

**缺陷 ②：统一根里显示的是本机物理文件夹名，不是挂载名（已修）**

- 现象：`PROPFIND /dav/` 里挂载项的 `<D:displayname>` 是 `diag-mount`（磁盘目录名），而 href 是 `/dav/我的电影/`。手机客户端一般**按 displayname 显示文件夹名** → 用户会看到一串物理目录名。
- 根因：`DavFS.Stat` 里那句「挂载点用挂载名对外」是**死代码**。`x/net/webdav` 的 `prop.go` 里 `props()` 是 `f, _ := fs.OpenFile(name, O_RDONLY, 0)` 然后 **`fi, _ := f.Stat()`**，`findDisplayName` 用的是这个 `fi.Name()` —— 走的是 `OpenFile().Stat()`，**不是** `FileSystem.Stat`。读分支原样返回 `os.OpenFile(phys)`，`(*os.File).Stat()` 给的就是物理目录名。
- 修法：读分支在挂载根（`t.Path == "/"`）返回包一层的 `davReadFile`，其 `Stat()` 用 `davAliasInfo` 只替换 `Name()`（`IsDir/Size/ModTime` 沿用真实信息）；`Stat()` 里原有的改名分支保留并加注释说明两处都要改。
- 实测：`<D:displayname>我的电影</D:displayname>` 且响应体内**不再出现** `phone-mount`。

**顺带修掉的探针自身错误（差点让验证变成空转）**

- Node 的 `fetch`（undici）**静默忽略 `init.auth`**（那是浏览器 XHR 的选项）。第一版 `probe-phone.mjs` 用它做 Basic Auth，结果所有请求都变成了"无认证"，**一整批 401 断言全部假通过**。必须自己拼 `Authorization: Basic base64(user:pass)`。批次 9 的 `probe-webdav.mjs` 本来就是自己拼的，所以不受影响。
- 两条断言把 fixture 写错了：挂载根 = 策略 `RootPath` 本身，所以 `/dav/<挂载名>/` 列出的是 `readme.txt` 与子目录 `电影/`，`a.mp4` 在 `/dav/<挂载名>/电影/`；PUT 落盘位置也是挂载根，不是 `电影/` 子目录。

### 7.7 批次 10：真机反馈 4 件事（滚动 / 离线下载 / m3u8 / 多网卡地址）（2026-09-11）

用户原话提到三件事（外加一条顺带），四项各自独立定位。

**① 「挂载的文件夹内容太多，无法上下滚动」（前端渲染缺陷，已修）**

- 现象：根视图/目录里的文件一多，列表被裁掉且**没有滚动条**。
- 根因：文件区容器是普通 block + 内联 `overflow:hidden`，而 `.file-list` / `.file-grid` 上写的是 `flex:1`。`flex:1` **只在 flex 父容器里生效** —— 在 block 父容器里它退化成普通块，于是列表按内容撑到 **3130px** 高（视口只有 661px），被 `overflow:hidden` 裁掉，且 `scrollHeight === clientHeight`，滚动条永远不出现。
- 修法：把该容器做成 `.file-area`（`display:flex; flex-direction:column` + `min-height:0`），并给它的直接子项（`.file-list` / `.file-grid`）补 `min-height:0` —— 后者默认 `min-height:auto`，会被内容撑开、把滚动能力压掉。
- 实测（`probe-scroll.mjs`，**13/13**）：网格 `clientHeight=474 / scrollHeight=3130`、列表 `474 / 10233`，用 CDP 真实滚轮驱动后 `scrollTop=600`，滚到底最后一个文件可见。**两种视图都测**（默认视图是网格，第一版只断言了列表，属"断言数错元素"）。

**② 「远程下载不支持」其实是「失败了看不到原因」（诊断能力缺失，已补）**

先做的是"把后端摘干净"，而不是直接改代码：

| 实测项 | 结果 |
| --- | --- |
| 公网 HTTP 直链 | ✅ 通（jsdelivr `left-pad/package.json` 成功落盘） |
| 磁力链 | ✅ 通（**12 秒**内连上 13 个做种 / 17 个节点，公共 tracker 生效） |
| 内网地址 | 默认被 SSRF 拒绝；开 `offline_allow_private` 后放行；关回后重新拒绝 |
| 取消磁力任务 | ✅ 状态落到 `canceled`，无残留 |

→ 结论：机制都在。用户看到的"不支持"是三类**不可诊断的失败**之一，逐类补了出口：

1. 卡在「正在获取种子信息」：BT 客户端启动时补挂 **10 个公共 tracker**（udp/https 各半）；运行中每 10 秒把「已连接 N 做种 / M 节点」回写进任务；3 分钟超时后明确列出三条常见原因（出站 UDP 被封 / 无人做种 / 磁力链已失效）。
2. 直链被防盗链：离线下载对话框新增 **Referer** 输入。
3. 源在内网被拒：管理台站点设置新增「离线下载 / 允许访问内网地址」开关（`offline_allow_private`，**默认关**），拒绝文案直接指路该开关。

前端任务行同步显示阶段提示与失败原因（`.tc-subline` / `.tc-subline.err`）—— 此前后端把原因写在 `error` 列里，界面上根本露不出来。

**③ 新增 m3u8（HLS）远程下载（新能力）**

- 新增 `server/internal/handler/m3u8.go`（约 700 行，纯 Go / 零第三方依赖 / 不需要 ffmpeg），融入既有离线任务链路（同队列、同进度、可取消、重启可恢复）。参考 N_m3u8DL-CLI 的能力面，落地这些：
  - master playlist 按 `BANDWIDTH` 降序**自动选最高码率**，`RESOLUTION` 记进任务供前端显示（「分片 3 / 3 · 1920x1080」）。
  - media playlist：`#EXTINF` / `#EXT-X-MEDIA-SEQUENCE` / `#EXT-X-ENDLIST` / `#EXT-X-BYTERANGE`（省略 offset 时**紧接上一段**）/ `#EXT-X-MAP`（合并时先写初始化段）。
  - `#EXT-X-KEY:METHOD=AES-128` 自动解密：显式 `IV=` 直用；**未给 IV 时按规范用媒体序号推导 16 字节大端 IV**；AES-128-CBC + PKCS7 去填充（校验填充一致才裁）。
  - 相对 URI（含 `#EXT-X-KEY` 的 `URI=`）一律按清单地址解析为绝对地址。
  - 默认 8 并发（上限 32），分片落磁盘临时区、按序合并、**边合并边删临时文件**；上限 20000 分片 / 20GB；开头连续失败即止损；取消不留半成品；支持自定义 `Referer` / UA；取数一律走 `ssrfHTTP`（SSRF 三层防护不动）。
  - **无 `.m3u8` 后缀的地址**：运行时按 `Content-Type: *mpegurl` 或正文 `#EXTM3U` 开头嗅探，命中就地切成 m3u8 链路（任务类型同步改）。
- **过程中修掉两个真缺陷**（都是探针当场抓到的，不是事后补测）：

### 7.11 批次 14：远程下载缓存清理与 BT 三个真缺陷（2026-09-13）

**① 用户反馈**

> 「BT下载以后其实都下好了 文件名字不对 没有copy过去 而是保留了缓存 没有删除，删除也不会删除缓存 这样会越来越大，其他m3u8和普通下载缓存完成以后copy到模板文件但是目录下面还是有缓存 导致越来越大」

**② 先证伪自己的假设：三处代码都已写了 `defer Remove`，为什么用户还说"没删"？**

三种链路的缓存位置（先查清）：
| 链路 | 缓存位置 | 代码里的清理 |
|---|---|---|
| HTTP 直链 | `%TEMP%/cp_offline_<taskID>.tmp` | `defer os.Remove(tmpPath)` |
| m3u8 (HLS) | `<data>/ziptmp/m3u8-<随机>/` | `defer os.RemoveAll(tmpDir)` |
| BT / 磁力 | `<data>/bt_tmp/<taskID>/` | `defer os.RemoveAll(dataDir)` |

`defer` **只在执行体正常返回时执行**。所以第一假设是"异常终止（强杀/断电/崩溃）导致残留"。为证实，写探针在本机跑了完整三链路 + 手工制造残留 + 重启，得到结论：

| 时点 | 实测结果 |
|---|---|
| 取消直链任务 | `cp_offline_<id>.tmp`（3.25 MB，正在写）**被清掉** ✅ |
| 直链失败（404） | 无残留 ✅ |
| 取消 BT 任务 | `bt_tmp/<id>/` **被清掉** ✅ |
| **手工放残留 + 完整重启** | `bt_tmp/99999/`（0.5 MB）与 `%TEMP%/cp_offline_88888.tmp`（0.25 MB）**都存活** ❌ |

→ **根因锁定**：正常流程本来就清；**真正的漏洞是"进程非正常退出后的残留无人回收"**（启动时不清、运行期也不清）。
另外在**用户真实机器**的 `%TEMP%` 里找到了 2 个 `cp_offline_*.tmp`（2026-09-12，2769B / 646B）—— 是用户自己踩到的那两个。

**③ BT 侧另外查出 3 个真缺陷（都是靠"本机做种 + 真实传输"测出来的）**

为了验证 BT 的**成功路径**，本轮专门写了两个小工具（都在 `.build-tmp/`，非交付物）：`btseed`（用 anacrolix 自己做种）、`bttracker`（极简 HTTP tracker），再用 `btmin` 做最小复现。结论：

| # | 缺陷 | 现象 | 后果 |
|---|---|---|---|
| 1 | **BT 监听端口固定 42069** | anacrolix 默认 `ListenPort: 42069`，而每个任务新建一个客户端 | **第二个并发 BT 任务必失败**：`first listen: listen tcp4 :42069: bind: Only one usage of each socket address` |
| 2 | **进度循环没有停滞超时** | 只有 `if total > 0 && done >= total { break }` | 拿不到 peer 时**永远卡在 processing 0%**，`bt_tmp/<id>` 一直占磁盘 —— 正是用户说的"下不动、缓存还不删"。实测 90 秒仍在 processing |
| 3 | **删除任务不碰磁盘** | `OfflineHandler.Delete` 只 `DB.Delete` | 用户按了删除，缓存原封不动 |

另外确认一条**不是 CloudPan 的锅**：`.torrent` 文件加载后，**tracker announce 从未发出**（本机 tracker 只收到做种端那一次 announce）。这是 anacrolix 在该环境下的行为，minimal 复现程序（`btmin`）同样如此 —— 因此 BT 连通性依赖 tracker/DHT 本身可用，CloudPan 无法凭空变出 peer。而**这恰恰让缺陷 2（无超时）的危害翻倍**：连不上 peer 时任务不会失败，只会无声地永远挂着。

**④ 改了什么**

新增 `server/internal/handler/cache.go`，把三处缓存路径收成**唯一事实来源**，并提供统一清扫：
- `offlineTmpPath(id)` / `btTaskDir(id)` / `m3u8TmpDirOf(zips, id)` —— 命名规则只写一处，执行体与清扫器共用
- `sweepTaskCaches()` —— 清 `bt_tmp/`、`ziptmp/m3u8-*`、`%TEMP%/cp_offline_*.tmp` 里**不属于活跃任务**的条目；只认本程序自己的命名（`bt_tmp` 下非纯数字目录、`ziptmp` 下非 `m3u8-` 前缀一律不碰），并给"1 分钟内写过"的缓存宽限，避免误伤刚落地的任务
- 挂载点：`InitTaskPool` 启动时清一次（**在 `resume()` 之前**，否则会把刚起的任务目录误判为残留）、`sweepLoop` 每 6 小时一次
- `purgeTaskCache(id)`：`run()` 的成功/失败/取消三条分支都调，`Cancel` 与 `Delete` 接口也各调一次

BT 侧（`bt.go`）：
- `btListenPortOf(taskID)` = `42300 + taskID % 500`，**并发任务各用各的端口**
- 进度循环加 `btStallTimeout = 5 分钟`：连续 5 分钟进度零增长即判失败，错误信息点明"没有做种者 / 出站被限 / tracker 与 DHT 都不可用"三种可能；进度有增长则重新计时（下载慢不会被误杀）
- 导入阶段的物理路径解析改为 `resolvePhys()`：依次试 `dataDir/<种子名>/<相对路径>` → `dataDir/<相对路径>` → `dataDir/<文件名>`。**这条修的是一个隐藏的重伤**：原先只按 `info.Name` 拼一次，拼不中就直接 `return error` → 任务判失败 → 紧接着 `defer os.RemoveAll` 把**刚下好的数据全删掉**，用户看到的就是"明明下好了却没进网盘"

m3u8（`m3u8.go`）：临时目录由 `os.MkdirTemp`（随机名）改为 **`m3u8-<taskID>`**（确定性命名），这样"取消/删除某个任务"能精确定位它的分片目录，不必靠"当前有没有 m3u8 任务"这种粗判据扫全目录。

**顺手修掉的一个潜伏 bug**：`TaskPool.Zips` 字段**从来没有被赋值过**（`InitTaskPool` 只设了 `Svc` 和 `BtDir`）。后果是 ① `runCompress` 的临时压缩包落在**当前工作目录**（相对路径），② 缓存清扫完全跳过 `ziptmp`。已改为 `InitTaskPool(svc, btDir, zipTmp)` 三个参数，`main.go` 传入 `cfg.Sub("ziptmp")`。

**⑤ 反向变异（证明这些修改真的在起作用）**

| 变异 | 期望 | 实测 |

## 8. 安全承诺

- 不碰 `server/data/`（数据库/密钥/回收站），不动你已挂载的真实目录内容。**唯一的例外**是批次 14 起的缓存清扫：它只清理**本程序自己命名的下载缓存**（`bt_tmp/<纯数字>`、`ziptmp/m3u8-<纯数字>`、`%TEMP%/cp_offline_<纯数字>.tmp`），且跳过当前活跃任务与 1 分钟内刚写过的条目；对挂载目录（用户真实数据）依然**一个字节都不动**。
- 数据库只做 AutoMigrate 加表/加列；**不自动删列**，需要时单独提确认。
- 对外接口契约不变：端口 `18322`、`CP_PORT`/`CP_DATA`/`CP_PUBLIC_URL`/`CP_TRUSTED_PROXIES`、`build.bat`/`start.bat` 用法（批次 13 起构建产物统一装配到 `out/`，脚本自身用法未变）。
- 每批改完提交一次 git，保证可回退。
