## 2. 已实测确认的核心风险（含证据）

### 2.1 【已实测复现】游客 24h 清理任务会物理删除文件，且绕过回收站

**证据（改前基线，2026-09-11 实测）**：在挂载策略根下放一个 mtime 为 3 天前的文件，服务重启后该文件消失；同目录 24h 内的文件保留。

```
### 1. [改前] 初始文件清单（游客有效目录 = 策略根/guest）
-rw-r--r--  fresh.txt      (刚刚)
-rw-r--r--  old.txt        (2026-09-08 20:09，3 天前)
### 4. [改前] 重启后文件清单
-rw-r--r--  fresh.txt      ← 仅剩新文件
>>> 判定 A：old.txt 已被物理删除 → 危害复现（绕过回收站）
```

**机制**：`handler/tasks.go:70 sweepGuestWorkspace()` 每小时（且**服务每次启动时立刻执行一次**）遍历所有 `type=local status=active` 的策略，对游客身份解析出的物理根做递归 mtime 清理，`os.Remove` 直接物理删除，不进回收站。

**为什么会波及你的文件**：清理范围 = 游客身份在该策略下的有效根。

- 隔离**开启**时：有效根 = `<挂载根>/guest` → 目前只会删到游客自己的目录（所以现在还没伤到你）。
- 隔离**关闭**后：有效根 = `<挂载根>` → **清理范围直接变成你挂载的整个文件夹**。

> 这正是"关隔离"和"删游客"必须**同一批、且先删清理任务**的原因。顺序反了，一小时内就会丢数据。

### 2.2 【已确认】本地盘按用户子目录隔离，与"挂载即可见"直接冲突

```go
// server/main.go:26-32（webdav.go:52-59 有同一份）
root := p.RootPath
if dir := fscore.UserDirOf(u); dir != "" {
    root = filepath.Join(root, dir)   // 挂 E:\电影 → 实际访问 E:\电影\admin
}
```

改动点仅这两处 + `fscore.UserDirOf`（`local.go:319`，全仓只被这两处调用）。

### 2.3 挂载入口不在文件管理器里，且没有"选文件夹"能力

- 唯一入口：管理控制台 → 存储策略 → 挂载存储；"物理目录"是**纯文本框**（`AdminConsole.vue:668-671`）。
- 服务端**没有**列本机目录的接口（唯一的列目录端点是 SSH 远端的 `terminal/fs/list`）。
- 结论：**「分配菜单」是新增功能**，不是改造。

> ✅ 已在批次 6（`687325b`）解决：新增 `handler/localdir.go` 的 `GET /api/admin/fs/dirs`（列本机目录）与 Explorer 内的「挂载文件夹」浏览式目录选择器；管理台的物理目录文本框保留为备用入口。

## 5. 批次 1 附带要处理的事：用户组删除后，那些"组参数"怎么办

删掉 `UserGroup` 后，原先从组里读的参数必须有固定值，否则会出现"读了空组 → 配额为 0 → 什么都传不上去"这类静默故障。预定固定值：

| 参数 | 原来源 | 固定值 |
| --- | --- | --- |
| 配额 | `UserGroup.QuotaMB` | **不限**（单用户内网，自己的盘） |
| 回收站保留天数 | `UserGroup.RecycleRetentionDays` | 30 天（保持现状语义） |
| 版本保留个数/天数 | `UserGroup.KeepVersions` / `VersionRetentionDays` | 维持现有默认值 |
| 允许分享/WebDAV/压缩/离线 | `Allow*` 系列 | 全部 `true` |
| 只读 | `ReadOnly` | `false` |
| 应用权限 | `AppPerms` | 全部开启（等价于管理员） |

> ⚠️ 这一项的影响面比"删两个路由"大得多：`fscore/service.go`、`fscore/versions.go`、`middleware/auth.go`、`handler/fs.go`、`bt.go`、`share.go`、`tasks.go` 都读组参数。我会在**批次 2** 单独做，并配"配额不限制 / 上传下载正常"的实测。

### 7.5 批次 9：删自更新接口 + WebDAV 统一入口（2026-09-11）

统一根的形状：

| 入口 | 内容 |
| --- | --- |
| `/dav/` | **虚拟根**：列出全部「已挂载的本机文件夹」。资源管理器 / 手机挂这一个地址即可看到全部 |
| `/dav/<挂载名>/` | 单个挂载：只想单独挂某一个时用 |
| `/dav/<盘符>/` | 兼容别名（旧文档写的是盘符），解析时兜底匹配 |

- 路径段 = **挂载名**（`/\:*?"<>|` 与控制字符替换为 `_`，首尾点和空格去掉；空名退回盘符）。同名挂载按 `名称-盘符` 去重，仍冲突再加序号。**路径段只由后端算**（`davPathOf()`），通过 `/api/admin/policies` 的 `davPath` 下发给界面，避免前后端各写一套命名规则。
- 顺带修掉遗留的 `/dav/<用户名>/…` 前缀校验：它让按 README 写的 `/dav/<盘符>/` 一律 403（这也是"WebDAV 一直没真正用过"的原因之一）。改由 `webdav.Handler{Prefix:"/dav"}` 剥前缀，href 也带 `/dav` 前缀。
- 本机挂载可读写：PUT/COPY 先写同目录临时文件、`Close` 时用 `LocalDriver.CreateFile` **原子替换**；`Mkdir` / `Move` / `Delete` 直连 os；**跨挂载 MOVE 被拒**（`errDavCrossMount`）；统一根是虚拟目录，写操作一律拒绝。
- 云盘挂载**不纳入 WebDAV**：云盘驱动的写语义无法在本机实测，与其在列表里摆一个连不出内容的空目录，不如不收；索引页会如实写"另有 N 个云盘挂载不经 WebDAV"。这是相对既有行为**无回归**的选择（旧实现 `resolve()` 本就只认 `type='local'`）。
- 自更新删除面：`handler/update.go`（536 行）、4 条路由、`model.UpdateLog` + AutoMigrate 条目、`main.go` 的 `SetUpdateListener` 与 `ErrClosed` 自重启分支（`errors`/`time` 两个 import 随之移除）。

### 7.6 批次 9 追加：手机端接入实测暴露的两个真缺陷（2026-09-11）

起因是问「运行以后手机端 WebDAV 怎么配账号密码」。为了给准确答案写了 `probe-phone.mjs` 走完整链路，结果**测出两个真缺陷**（都不是人为注入）。

**认证链路（先说清事实，避免继续按旧假设用）**

| 项 | 事实 |
| --- | --- |
| 账号 | 网页登录用户名（`admin`） |
| 密码 | **WebDAV 独立密码**（`PUT /api/users/me/webdav-password`，存 `user.webdav_password_hash`）——**不是**登录密码；未设置时服务端回 401「WebDAV 密码错误（请在设置中先行设置）」 |
| 地址 | `http://<内网IP>:18322/dav/`（统一入口）；单挂载 `…/dav/<挂载名>/` |
| 前置开关 | `SiteSetting.webdav_enabled`（默认 `true`，管理台可关，关后 403）与 `AppEnabled("webdav")`（清单默认启用） |
| 失败锁定 | 与网页登录**共用**同一张失败锁定表（IP+用户名，5 次锁 15 分钟）；认证成功即清零 |

**缺陷 ①：PUT 到「目录」会把目录删掉换成文件（数据破坏，已修）**

- 现象：`PUT /dav/<挂载名>/`（带内容）→ **`201 Created`**；磁盘上那个挂载文件夹已经**变成一个文件**（实测 `readdirSync` 直接抛 `ENOTDIR`）。
- 根因链：`LocalDriver.CreateFile`（`fscore/local.go:257`）是 `os.MkdirAll(Dir(phys))` → 写 `phys+".cp-part"` → **`os.Remove(phys)`** → `Rename(tmp, phys)`。当 `phys` 指向**空目录**时，Windows 上 `os.Remove` 对空目录**成功**，于是目录被删、临时文件改名顶上。目录非空时 `os.Remove` 失败，只是报错（相对安全）。
- 可达性：`webdav` 的 `handlePut` 不做 IsDir 前置检查，直接 `OpenFile(..., O_RDWR|O_CREATE|O_TRUNC, 0666)`；`COPY` 目标同理。
- 修法：在 `DavFS.OpenFile` 的写入分支先 `os.Stat(phys)`，命中目录就**返回拒写对象**而不是落盘 —— `davRejectWriteFile` 的 `Write`/`Close` 都返回 `errDavIsDir`，`io.Copy` 与 `Close` 任一失败都会让 webdav 落到 `405 Method Not Allowed`（RFC 4918 对"向集合 PUT"的规定），**一个字节都不落盘**。
- 实测：修前 `PUT` = 201 且目录消失；修后 `PUT` = **405**，`[目录] 内容=[]` 完好。`MKCOL`/`DELETE`/`MOVE`/`COPY` 到挂载根同样 4xx 且目录不受影响。

**缺陷 ②：统一根里显示的是本机物理文件夹名，不是挂载名（已修）**

- 现象：`PROPFIND /dav/` 里挂载项的 `<D:displayname>` 是 `diag-mount`（磁盘目录名），而 href 是 `/dav/我的电影/`。手机客户端一般**按 displayname 显示文件夹名** → 用户会看到一串物理目录名。
- 根因：`DavFS.Stat` 里那句「挂载点用挂载名对外」是**死代码**。`x/net/webdav` 的 `prop.go` 里 `props()` 是 `f, _ := fs.OpenFile(name, O_RDONLY, 0)` 然后 **`fi, _ := f.Stat()`**，`findDisplayName` 用的是这个 `fi.Name()` —— 走的是 `OpenFile().Stat()`，**不是** `FileSystem.Stat`。读分支原样返回 `os.OpenFile(phys)`，`(*os.File).Stat()` 给的就是物理目录名。
- 修法：读分支在挂载根（`t.Path == "/"`）返回包一层的 `davReadFile`，其 `Stat()` 用 `davAliasInfo` 只替换 `Name()`（`IsDir/Size/ModTime` 沿用真实信息）；`Stat()` 里原有的改名分支保留并加注释说明两处都要改。
- 实测：`<D:displayname>我的电影</D:displayname>` 且响应体内**不再出现** `phone-mount`。

**顺带修掉的探针自身错误（差点让验证变成空转）**

- Node 的 `fetch`（undici）**静默忽略 `init.auth`**（那是浏览器 XHR 的选项）。第一版 `probe-phone.mjs` 用它做 Basic Auth，结果所有请求都变成了"无认证"，**一整批 401 断言全部假通过**。必须自己拼 `Authorization: Basic base64(user:pass)`。批次 9 的 `probe-webdav.mjs` 本来就是自己拼的，所以不受影响。
- 两条断言把 fixture 写错了：挂载根 = 策略 `RootPath` 本身，所以 `/dav/<挂载名>/` 列出的是 `readme.txt` 与子目录 `电影/`，`a.mp4` 在 `/dav/<挂载名>/电影/`；PUT 落盘位置也是挂载根，不是 `电影/` 子目录。

## 8. 安全承诺
