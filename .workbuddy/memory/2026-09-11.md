### 二、WebDAV 统一入口设计

**入口形状（三条并存）**

| 地址 | 语义 | 可写 |
| --- | --- | --- |
| `/dav/` | **虚拟根 = 全部本机挂载**，PROPFIND 列出一层挂载名 | ❌ 只读（MKCOL/PUT/DELETE/MOVE 均拒） |
| `/dav/<挂载名>/…` | 单个挂载，**正式路径段** | ✅ 读写删 |
| `/dav/<盘符>/…` | 兼容旧写法的别名（`/dav/M/…`），界面永不展示 | ✅ |

**6 条设计要点**

1. `davPrefix = "/dav"` 交给 `webdav.Handler{Prefix}`；webdav 自己 `stripPrefix`，且 PROPFIND 的 `href = path.Join(h.Prefix, reqPath)` —— 所以 **href 会自动带前缀**，不用手拼。
2. **路径段命名规则只在后端**：`davSeg(name, letter)` 把 `/\:*?"<>|` 与控制字符换成 `_`、`strings.Trim(s, " .")`、空则退 `letter`、再空则 `"mount"`；重名加 `-<letter>`、再冲突加 `-2`。经 `PolicyList` 的 **`davPath` 字段**下发给前端展示，避免前后端各写一套规则。
3. **统一根只列 `type='local'` 的挂载**，且只列 `status <> 'disabled'` 的。
4. `davTarget(name)` 用 `strings.Cut(p, "/")` 拆成 `{Mount, Path}`；`Mount == nil` 即统一根。
5. **统一根上的写操作一律拒绝**（`Mkdir`/`RemoveAll`/`Rename` 判 `Mount == nil` 直接报错）。
6. **跨挂载 MOVE/COPY 显式拒绝**（`errDavCrossMount`）：webdav 的 `MOVE` 在目的地已存在且 `Overwrite=T` 时是 **先 `RemoveAll` 再 `Rename`** —— 不拦的话会**先删掉源盘的文件**。

**顺手修掉的遗留缺陷（这才是"WebDAV 一直没真正用过"的原因）**

`DavAuth()` 里有段 `/dav/{username}/…` 的前缀校验 + `c.Request.URL.Path` 改写。而 README 写的是 `/dav/<盘符>/…`，**按文档写的地址一律 403**。本次删掉这段校验。

### 三、实测抓到的真实缺陷（不是人为注入）

`davWriteFile.Close()` 残留 `.cp-put-*` 临时文件。原因：

```go
defer src.Close()     // 晚于下面这行执行
_ = os.Remove(tmp)    // Windows 上删一个仍被打开的句柄会失败，且错误被忽略
```

改成显式 `_ = src.Close()` 后再 `os.Remove(tmp)`，并加注释。**这是首轮 44 项实测里直接 FAIL 出来的，不是变异验证造出来的。**

### 四、一个设计取舍：云盘不纳入 WebDAV

首轮实现把云盘挂载也列进了统一根，但 `PROPFIND /dav/云盘测试/` 返回 **200 而非错误**（因为云盘分支根本没实现）。决定**不收**：

- 写语义无法本机实测（GitHub 上该驱动曾有"建了不存在的目录"的 issue）；
- 与其在统一根里摆一个点进去是空的目录，不如不收；
- 旧实现 `resolve()` 本就只认 `type='local'`，**无回归**。

改为：`DavMounts()` 加 `type = ?` 过滤；索引页用 `davNonLocalNames()` 如实写明「另有 N 个云盘挂载不经 WebDAV」。

### 五、运维工具链的收获

- **webdav.File 接口要 6 个方法**（`Read/Write/Seek/Close/Readdir/Stat`）。只读实现缺 `Write` 直接编译不过 → 补 `func (r *davDirFile) Write([]byte) (int, error) { return 0, errDavReadOnly }`。
- `webdav.Handler` 在 `os.IsNotExist` 时：PUT → **409**、MKCOL → **409**、PROPFIND → **404**。写断言要按这个来。
- `OpenFile` 的 `os.MkdirAll(filepath.Dir(phys))` **只能挂在 `write == true` 分支**——读请求绝不能凭一个不存在的路径去建目录。
- `davLocal(m)` 必须用 `&fscore.LocalDriver{Root: abs}` 直接构造，**不能调 `NewLocal()`**（`NewLocal` 内部是 `MkdirAll`，会静默建目录）。
- 统一注册 `GET /dav` 与 `GET /dav/*rest` 走**同一个闭包**：否则无尾斜杠分支不套 auth，`GET /dav/` 未认证返回 403 而非 401。

### 起因与真实结论（认证链路，别再按旧假设用）

| 账号 | 网页登录用户名（`admin`） |
| 密码 | **WebDAV 独立密码**（`PUT /api/users/me/webdav-password` → `user.webdav_password_hash`），**不是登录密码** |
| 未设独立密码时 | 401「WebDAV 密码错误（请在设置中先行设置）」——任何账号都进不去 |
| 地址 | `http://<内网IP>:18322/dav/`（统一入口）；单挂载 `…/dav/<挂载名>/` |
| 前置开关 | `SiteSetting.webdav_enabled` 默认 `true`（管理台可关，关后 403）；`AppEnabled("webdav")` 清单默认启用 |
| 失败锁定 | 与网页登录**共用**同一张表（IP+用户名，5 次锁 15 分钟）；成功即清零 |

设置入口：**设置（SettingsApp）→ WebDAV 独立密码**；启用开关在**管理控制台 → 设置 → WebDAV**。

### 缺陷 ①：PUT 到「目录」会把目录删掉换成文件（数据破坏）

- 现象：`PUT /dav/<挂载名>/`（带内容）→ **`201 Created`**，磁盘上那个挂载文件夹**已经变成一个文件**（实测 `readdirSync` 抛 `ENOTDIR`）。
- 根因链：`fscore/local.go:257 CreateFile` = `os.MkdirAll(Dir(phys))` → 写 `phys+".cp-part"` → **`os.Remove(phys)`** → `Rename(tmp, phys)`。当 `phys` 是**空目录**时，Windows 上 `os.Remove` 对空目录**成功** → 目录被删、临时文件顶上。目录非空时 `os.Remove` 失败，只是报错（相对安全）。
- 可达性：`webdav` 的 `handlePut` 不做 IsDir 前置检查，直接 `OpenFile(..., O_RDWR|O_CREATE|O_TRUNC, 0666)`；`COPY` 目标同理。
- 修法：`DavFS.OpenFile` 写入分支先 `os.Stat(phys)`，命中目录就返回**拒写对象**（`davRejectWriteFile`：`Write`/`Close` 都返回 `errDavIsDir`），让 webdav 落到 **405 Method Not Allowed**（RFC 4918 对"向集合 PUT"的规定），**一个字节都不落盘**。
- 实测：修前 201 且目录消失；修后 405，`[目录] 内容=[]` 完好。`MKCOL`/`DELETE`/`MOVE`/`COPY` 到挂载根同样 4xx 且目录不受影响。

### 缺陷 ②：统一根的 displayname 是物理目录名，不是挂载名

- 现象：PROPFIND `/dav/` 里挂载项 `<D:displayname>diag-mount</D:displayname>`（磁盘目录名），而 href 是 `/dav/我的电影/`。手机客户端一般**按 displayname 显示文件夹名** → 用户看到一串物理目录名。
- 根因：`DavFS.Stat` 里那句「挂载点用挂载名对外」是**死代码**。`x/net/webdav` 的 `prop.go` `props()` 是 `fs.OpenFile(name, O_RDONLY, 0)` 然后 **`f.Stat()`**，`findDisplayName` 用这个 `fi.Name()` —— 走 `OpenFile().Stat()`，**不是** `FileSystem.Stat`。读分支原样返回 `os.OpenFile(phys)`，`(*os.File).Stat()` 给的就是物理目录名。
- 修法：读分支在挂载根返回包一层的 `davReadFile`，其 `Stat()` 用 `davAliasInfo` 只替换 `Name()`（`IsDir/Size/ModTime` 沿用真实信息）；`Stat()` 里的改名分支保留并加注释说明**两处都要改**。
- 实测：`<D:displayname>我的电影</D:displayname>`，响应体内**不再出现** `phone-mount`。

### 探针自身的错误（差点让整批断言变空转）

1. **Node 的 `fetch`（undici）静默忽略 `init.auth`**（那是浏览器 XHR 的选项）。第一版 `probe-phone.mjs` 用它做 Basic Auth → 所有请求变成"无认证" → **一整批 401 断言全部假通过**（16 PASS / 15 FAIL 里那些 PASS 全是空转）。必须自己拼 `Authorization: Basic base64(user:pass)`。批次 9 的 `probe-webdav.mjs` 本来就是自己拼的，所以它的 44/44 不受影响。
2. 两条断言把 fixture 写错了：**挂载根 = 策略 `RootPath` 本身**，所以 `/dav/<挂载名>/` 列出的是 `readme.txt` 与子目录 `电影/`；`a.mp4` 在 `/dav/<挂载名>/电影/`；PUT 落盘位置也是挂载根而非 `电影/`。
3. 断言预期值手写了固定字符串却与实际 `.sort()` 顺序不同 → 改用"两边都 sort 后比较"。
